Part 1 — Three-Signal Inference Engine
ASignal Priority Order
1
Highest priority
Correction Learning
Checks correctionHistory array first. If tweet content contains a previously corrected keyword pattern, the learned category is returned immediately. Signals 2 and 3 are skipped entirely.
Source: xrecall_corrections in localStorage. Persists across sessions. Pattern extracted from first matched keyword or first 3 words of tweet content.
Confidence: 0.88 to 0.98
2
Secondary signal
Semantic Analysis
Keyword dictionary lookup across 12 categories and 100+ domain-specific terms. Matches on full tweet content AND author name simultaneously.
Existing user folders checked first (Pass 1). Only attempts new category creation if no existing folder matches (Pass 2). Best match wins — highest keyword count.
Confidence: 0.52 to 0.87
3
Supporting signal
Author Authority
Bayesian prior from account name. ESPN = high probability of Sports. BBCNews = high probability of News. Contributes to final match score alongside semantic keywords.
Overridden by semantic analysis when the semantic signal is strong. Not a standalone signal — works in combination with Signal 2 keyword matching.
Confidence: 0.52 to 0.87

Part 4 — Trust Score System
DDynamic trust score
+2
Reward
Every accepted save where the user does not move the tweet. Every bookmark removal from Library. Max cap: 100.
-4
Penalty
Every manual folder move — the AI was wrong. Penalty is larger than reward to bias the system toward accuracy. Min floor: 0.
75
Starting value
Every session starts at 75. Trust score lives in React state only — resets on reload. Corrections are persisted, trust score is not.
Effect on confidence ceiling
Trust bonus = trustScore / 100 x 0.06. A user at trust 100 gets +0.06. A user at trust 0 gets +0.00. The ceiling moves from 0.87 to 0.93 between worst and best trust. Threshold stays fixed at 0.75 regardless.
Why corrections persist but trust does not
Correction history is the valuable signal — it contains the learned patterns. Trust score is a session-level quality indicator. Resetting trust to 75 on each session prevents stale penalty accumulation while keeping the learned vocabulary intact.
Part 5 — Correction Learning Loop
EHow the AI learns from user behavior
Full correction loop — end to end
Step 1: User bookmarks a tweet. Signal 2 classifies it as "Technology" based on keyword "ai".
Step 2: User opens Library, taps the tweet menu, selects "Move to folder", picks "Dev Resources" instead.
Step 3: CorrectionRecord is written: tweetId · oldCategory "Technology" · newCategory "Dev Resources" · keywordPattern "ai" · timestamp.
Step 4: Trust score drops by 4. Correction record persisted to xrecall_corrections in localStorage.
Step 5: User bookmarks another tweet containing "ai". Inference engine checks correctionHistory first. Finds "ai" pattern. Returns "Dev Resources" at confidence 0.88 to 0.98. Skips semantic and author signals entirely.
Result: The AI now correctly categorizes "ai" tweets into Dev Resources instead of Technology — permanently, across sessions.
keywordPattern extraction logic
First choice: the first matched keyword from bookmarkMeta.matchedKeywords. Fallback: first 3 words of tweet content joined as a string. This ensures even tweets with no keyword match have a learnable pattern stored.
Persistence across sessions
correctionHistory is written to xrecall_corrections on every move. On next app load, useState lazy initializer reads it back from localStorage. The AI has full memory of every correction the user has ever made.
